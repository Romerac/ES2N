## 🏃 1. SCRUM - Foco em Gestão de Projetos

### 👥 Papéis

| Papel | Responsabilidade |
|-------|------------------|
| **Product Owner** | Dono do produto; define prioridades e gerencia o Product Backlog |
| **Scrum Master** | Facilitador; remove impedimentos e garante o cumprimento do Scrum |
| **Time de Desenvolvimento** | Equipe multifuncional que entrega o incremento do produto |

### 📦 Artefatos

| Artefato | Descrição |
|----------|-----------|
| **Product Backlog** | Lista priorizada de todos os requisitos e funcionalidades desejadas |
| **Sprint Backlog** | Itens selecionados do Product Backlog para serem desenvolvidos na Sprint |
| **Incremento** | Versão pronta e funcional do produto ao final de cada Sprint |

### 🔄 Eventos (Cerimônias)

| Evento | Descrição |
|--------|-----------|
| **Sprint** | Ciclo de trabalho com duração fixa (geralmente 2 a 4 semanas) |
| **Sprint Planning** | Planejamento do que será entregue na Sprint |
| **Daily Scrum** | Reunião diária de 15 minutos para alinhamento do time |
| **Sprint Review** | Revisão do incremento com stakeholders |
| **Sprint Retrospective** | Reunião para melhoria contínua do processo |

### 🏛️ Pilares do SCRUM

- 🔍 Transparência
- 👁️ Inspeção
- 🔧 Adaptação

## ⚡ 2. XP (Extreme Programming) - Foco em Práticas Técnicas

### 💎 Valores

- Comunicação
- Simplicidade
- Feedback
- Coragem
- Respeito

### 🛠️ Práticas Principais

**📋 Planejamento**
- Jogo do Planejamento: Priorização de funcionalidades com o cliente

**📊 Gestão**
- Entregas Pequenas e Frequentes: Releases curtos e constantes
- Ritmo Sustentável: Jornada de trabalho equilibrada para evitar burnout

**🔧 Engenharia**

| Prática | Descrição |
|---------|-----------|
| **Programação em Pares** | Dois desenvolvedores trabalhando juntos em uma estação |
| **Integração Contínua** | Código integrado e testado várias vezes ao dia |
| **Refatoração** | Melhoria contínua do código sem alterar comportamento |
| **TDD** | Test-Driven Development - testes escritos antes do código |
| **Propriedade Coletiva** | Qualquer membro pode modificar qualquer parte do código |

**🎨 Design**
- Projeto Simples: A solução mais simples que funciona
- Metáfora: Sistema de nomenclatura compartilhado para facilitar comunicação

### 👤 Papéis no XP

| Papel | Função |
|-------|--------|
| **Programador** | Desenvolve o código e aplica as práticas técnicas |
| **Cliente** | Define histórias de usuário e prioriza funcionalidades |
| **Rastreador (Tracker)** | Monitora o progresso e ajusta o planejamento |

## 📐 3. RUP (Rational Unified Process) - Foco em Estrutura e Disciplina

### 🧩 Características

- 🔄 Iterativo
- 📈 Incremental
- 📋 Formal
- 📖 Orientado a Casos de Uso

> ⚠️ **Nota:** O RUP é mais pesado e estruturado que as metodologias ágeis puras, sendo recomendado para projetos de grande porte com requisitos bem definidos.

### 📅 Fases (Dimensão Temporal)

| Fase | Objetivo |
|------|----------|
| **1. Concepção (Inception)** | Definir escopo, viabilidade e objetivos do projeto |
| **2. Elaboração (Elaboration)** | Analisar riscos e definir a arquitetura base do sistema |
| **3. Construção (Construction)** | Desenvolver e testar o software (maior parte da codificação) |
| **4. Transição (Transition)** | Entregar o produto final, treinamento e implantação |

### 📋 Disciplinas (Fluxos de Trabalho)

- 📊 Modelagem de Negócios
- 📝 Requisitos
- 🏗️ Análise e Design
- 💻 Implementação
- 🧪 Teste
- 🚀 Implantação
- 📋 Gerenciamento de Projetos
- ⚙️ Configuração e Gerenciamento de Mudanças

## 🔄 Comparativo Resumido

| Aspecto | SCRUM | XP | RUP |
|---------|-------|-----|-----|
| **Foco** | Gestão de Projetos | Práticas Técnicas | Estrutura e Disciplina |
| **Nível de Formalidade** | Médio | Baixo | Alto |
| **Iterações** | Sprints (2-4 semanas) | Releases curtas | Fases (longas) |
| **Documentação** | Mínima | Mínima | Extensa |
| **Papéis Principais** | PO, SM, Time | Programador, Cliente, Tracker | Analista, Arquiteto, Dev, Testador |
| **Melhor para** | Equipes pequenas/médias | Equipes técnicas maduras | Grandes projetos corporativos |
